# OfferBot — PostgreSQL + Railway

Проект использует **PostgreSQL**, а не SQLite. При первом запуске бот создаёт таблицы автоматически. Старые базы и данные не импортируются.

## Что реализовано

- `/start` просит подписаться на `@dodep222`; кнопка подтверждения проверяет подписку по ID канала `-1004393569613`.
- После подтверждения показываются кнопки «Купить доступ», «Инструкция», «Техподдержка».
- После подтверждённой оплаты доступ выдаётся автоматически; пользователю приходит кнопка чата покупателей `https://t.me/+DrIdLrR8zLs3NWJi`.
- Админская рассылка: `/broadcast`, затем отправить следующее сообщение — текст, фото, видео или GIF. Бот копирует его пользователям, которые запускали бота. `/cancel` отменяет рассылку.
- Уведомление владельцу отправляется при новом/повторном включении Telegram Business-подключения; отключение не вызывает такое уведомление.
- В офере есть только кнопки «Принять» и «Отклонить», а после принятия — только кнопка передачи. «Подтвердить передачу» и логика подтверждения удалены.
- Оферы поддерживают русский, английский, китайский и арабский. Язык можно написать после команды или в конце.
- Для рублей сумма показывается без пробела: `2000₽`.
- Сохранены реферальные ссылки и разовое начисление 3 TON за покупку приглашённого пользователя. Автоматической выплаты реферального баланса нет.
- Истёкшие ожидающие оферы удаляются каждые 15 минут.

```text

офер https://t.me/nft/PartySparkler-140864 4500 зв англ
офер https://t.me/nft/PartySparkler-140864 4500 stars китай
```

Языковые сокращения: `англ`, `китай`, `араб`; также принимаются `en`, `cn`/`zh`, `ar`. По умолчанию русский.

## Создание PostgreSQL и деплой на Railway

1. В Railway открой проект → **New** → **Database** → **PostgreSQL**.
2. Дождись, пока PostgreSQL станет доступен.
3. Добавь сервис бота из GitHub-репозитория с файлами этого проекта.
4. В сервисе бота открой **Variables** и добавь переменные из списка ниже.
5. Для `DATABASE_URL` используй Railway Reference Variable на URL PostgreSQL. Если сервис базы называется `Postgres`, обычно это `${{Postgres.DATABASE_URL}}`; если имя другое, выбери соответствующую переменную сервиса базы.
6. В настройках Deploy укажи Start Command: `python bot.py`.
7. Запусти деплой и проверь логи. При первом старте бот подключится к PostgreSQL и создаст таблицы.

**Важно:** в канал `@dodep222` добавь бота администратором, чтобы Telegram разрешал проверять членство через `getChatMember`. Достаточно минимальных прав, необходимых для проверки подписчиков. Если бот не может получить статус участника, проверка подписки будет считаться неуспешной.

## Variables для сервиса бота

Обязательные:

- `BOT_TOKEN` — новый токен из BotFather.
- `OWNER_ID` — числовой Telegram ID владельца.
- `DATABASE_URL` — Reference Variable из PostgreSQL-сервиса Railway.
- `TON_WALLET` — кошелёк для оплаты.
- `PAYMENT_AMOUNT` — цена доступа в TON/Gram.

Настройки ссылок и подписки (значения уже имеют значения по умолчанию, но можно задать явно):

- `CHANNEL_ID=-1004393569613`
- `CHANNEL_URL=https://t.me/dodep222`
- `USERS_CHAT_URL=https://t.me/+DrIdLrR8zLs3NWJi`
- `SUPPORT_URL=https://t.me/witensea` — замени, если поддержка находится в другом аккаунте/чате.

Дополнительные:

- `OFFER_ACCESS_MODE=owner` — доступ только владельцу и пользователям из списка разрешённых.
- `OFFER_ALWAYS_ALLOWED_IDS=` — необязательные ID через запятую.
- `OFFER_EXPIRE_HOURS=24`
- `BUSINESS_DEBUG=0`
- `OFFER_HELP_URL=` — необязательная ссылка на справку.

`DATABASE_PATH` больше не используется и добавлять его не нужно. Не добавляй SQLite-файл или Railway Volume для базы: данные находятся в PostgreSQL-сервисе.

## Важное по безопасности

Не загружай `.env` в GitHub и не вставляй токен в исходный код. Токен, который был в присланном файле `.env`, следует отозвать/перевыпустить через `@BotFather` и указать новый в Railway.

## Проверка перед запуском

```bash
python -m py_compile bot.py config.py database.py offer.py
```

Полноценная проверка реальной подписки, Business-обновлений и блокчейн-платежей возможна только после запуска с настоящим ботом, Telegram-каналом и PostgreSQL Railway.


## Админка

Команда `/admin` открывает компактное меню с кнопками статистики, истории платежей, Business-подключений и рассылки. Успешная проверка TON-платежа атомарно отмечает платёж оплаченным и выдаёт доступ в PostgreSQL; владельцу отправляется короткое уведомление с переходом в историю платежей. Проверка TON Center ограничена коротким тайм-аутом.
